# ShareView 테스트 시나리오

대상: `index.html` + `screenShare.js` (PeerJS 기반 P2P 화면공유/채팅/파일공유)
사전 준비: `npm start` 로 로컬 서버(포트 3000, 시그널링 9000) 실행, 실제 화면 공유 테스트는 getDisplayMedia를 지원하는 일반 브라우저(Chrome/Edge) 2개 창(Host/Viewer) 또는 PC 2대 필요.

## 1. 서버/초기 로딩

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 1-1 | 서버 정상 기동 | `npm start` 실행 | 콘솔에 `Web Server: http://localhost:3000` 출력, 프로세스 유지 |
| 1-2 | 페이지 최초 로드 | `http://localhost:3000` 접속 | 좌측 컨트롤 패널 + 우측 "Ready to Connect" 플레이스홀더 노출, ID: Not Set |

## 2. ID 설정 (Host/Viewer 공통)

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 2-1 | 커스텀 ID로 설정 | ID 입력 후 Set 클릭 | `peer.on('open')` 발생, ID 라벨에 반영, "ID 설정 완료" alert, Start Sharing 버튼 활성화 |
| 2-2 | ID 미입력 후 Set | 입력칸 비운 채 Set 클릭 | 랜덤 ID로 peer 생성, 정상 open |
| 2-3 | 중복 ID 사용 | 이미 접속 중인 ID로 Set | `unavailable-id` 에러 → "이미 사용 중인 ID입니다" alert, ID 라벨 "ID 오류", peer는 null 처리되어 재시도 가능 |
| 2-4 | 연결된 상태에서 ID 재설정 | 이미 ID 설정된 상태에서 다시 Set | "새로운 ID로 변경하시겠습니까?" confirm → 확인 시 기존 peer destroy 후 재생성, 취소 시 아무 변화 없음 |

## 3. Host: 화면 공유

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 3-1 | 화면 공유 시작 | ID 설정 후 "Start Sharing (with Audio)" 클릭 → 화면/윈도우 선택 | 내 미리보기(`#screen-preview`)에 스트림 표시, muted 상태, "Ready to Connect" 플레이스홀더 숨김 |
| 3-2 | 공유 중 사용자가 브라우저 "공유 중지" 클릭 | 공유 중 OS/브라우저 제공 중지 버튼 클릭 | `onended` 트리거 → srcObject null, 플레이스홀더 재노출 |
| 3-3 | 화면 선택 취소 | 공유 시작 후 선택 창에서 취소 | catch 블록에서 콘솔 에러만 남고 앱은 정상 상태 유지 (크래시 없음) |
| 3-4 | 비보안 컨텍스트(HTTP, non-localhost)에서 시도 | HTTPS/localhost가 아닌 주소로 접속 후 공유 시작 | getDisplayMedia 미지원 alert 노출, 콘솔 에러 로그 |

## 4. Viewer: Host 연결

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 4-1 | 정상 연결 | Host ID 입력 후 Connect | 자동 전체화면 진입, `call.on('stream')`으로 원격 화면 수신 후 표시(음소거 해제), 플레이스홀더 숨김 |
| 4-2 | Host ID 미입력 | 빈 값으로 Connect 클릭 | "친구의 ID를 입력해주세요" alert, 연결 시도 안 함 |
| 4-3 | 존재하지 않는 Host ID | 잘못된 ID로 Connect | `call.on('error')` → "연결 중 오류가 발생했습니다" alert |
| 4-4 | 공유 중이 아닌 Host에 연결 | Host가 Start Sharing 하지 않은 상태에서 Connect | 데이터 채널은 연결되지만 영상 스트림 없음 (스트림 없이 answer) |
| 4-5 | 연결 종료 | Host가 공유 종료/연결 끊김 | `call.on('close')` → 화면 초기화, 전체화면 자동 해제 |

## 5. 참가자 목록 (Host)

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 5-1 | Viewer 접속 시 목록 갱신 | Viewer가 Connect | Host 화면의 참가자 목록에 Viewer ID 추가, "Welcome to the session!" 시스템 메시지 전송 |
| 5-2 | Viewer 다수 접속 | Viewer 2명 이상 접속 | 각각 목록에 추가됨 |
| 5-3 | Viewer 연결 종료 | Viewer 탭 종료/연결 끊김 | 목록에서 해당 ID 제거 |

## 6. 채팅

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 6-1 | Viewer → Host 메시지 | Viewer가 메시지 입력 후 Send | Host 채팅창에 수신, Host가 다른 Viewer에게 브로드캐스트 |
| 6-2 | Host → Viewer 메시지 | Host가 메시지 입력 후 Send | 연결된 모든 Viewer 채팅창에 표시 |
| 6-3 | 다자간 브로드캐스트 | Viewer A가 메시지 전송, Viewer B도 연결된 상태 | Host 경유하여 Viewer B에게도 전달 |
| 6-4 | 빈 메시지 전송 | 입력 없이 Send 클릭 | 아무 동작 안 함 (전송 안 됨) |

## 7. 파일 공유 (드래그 앤 드롭)

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 7-1 | 소용량 파일 전송 | 채팅 영역에 파일 드래그 드롭 | "Sending file..." 시스템 메시지 → 청크 전송 → 상대방 채팅에 다운로드 링크 노출 → "File sent successfully" |
| 7-2 | 대용량 파일 전송(수 MB~) | 큰 파일 드롭 | 청크 단위(16KB) 순차 전송, 중간 끊김 없이 완료, 수신측에서 정상 다운로드/열람 가능 |
| 7-3 | 수신측 다운로드 | 전송 완료 후 링크 클릭 | Blob URL로 원본 파일 정상 다운로드 |
| 7-4 | 드래그 오버 시각 효과 | 파일을 채팅 영역 위로 드래그 | `drag-over` 클래스 적용되어 드롭존 하이라이트, 영역 벗어나면 해제 |

## 8. 전체화면 & 사이드바 자동 숨김

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 8-1 | 전체화면 토글 버튼 | Fullscreen 버튼 클릭 | 전체화면 진입, exit 버튼 노출 |
| 8-2 | Esc로 전체화면 해제 | 전체화면 중 Esc 입력 | `fullscreenchange` 이벤트로 exit 버튼 숨김, 사이드바 복원 |
| 8-3 | 사이드바 자동 숨김 ON | 체크박스 켠 채 전체화면 진입 | 사이드바 숨겨짐 |
| 8-4 | 사이드바 자동 숨김 OFF | 체크박스 끈 채 전체화면 진입 | 사이드바 유지 |
| 8-5 | 설정값 유지 | 토글 후 새로고침 | localStorage에 저장된 값(`hideSidebarOnFullscreen`)이 체크박스에 반영 |

## 9. 예외/장애 케이스

| # | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| 9-1 | 시그널링 서버 다운 중 접속 | 서버 종료 상태에서 페이지 로드 후 ID 설정 시도 | peer 연결 실패, 콘솔 에러 (서버 크래시 없이 사용자에게만 영향) |
| 9-2 | 서버 프로세스 중 미처리 예외 발생 | 비정상 입력 등으로 핸들러 에러 유발 | 최근 추가된 글로벌 에러 핸들러(`server.js`)로 서버 프로세스는 죽지 않고 유지 |
| 9-3 | 네트워크 중간 단절 | Host/Viewer 중 한쪽 네트워크 차단 | 반대쪽에서 `close`/`error` 이벤트로 연결 정리, UI가 멈추지 않음 |
| 9-4 | 카메라/마이크 권한 거부 | 브라우저 권한 요청에서 거부 | catch로 에러만 로깅, alert 없이 조용히 실패(현재 동작) — UX상 사용자 피드백 필요 여부 확인 |
