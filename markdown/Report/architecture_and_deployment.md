# P2P 교육용 시스템 아키텍처 및 배포 가이드

## 1. 아키텍처 개요 및 상용 서비스(Zoom, Discord)와 비교
본 프로젝트는 **WebRTC** 기술을 기반으로 하며, 이는 Zoom이나 Discord와 같은 대형 상용 서비스가 사용하는 핵심 기술과 동일합니다. 그러나 **연결 토폴로지(구조)**에서 결정적인 차이가 있습니다.

### 1.1. 공통점 (Core Technology)
모든 서비스가 **WebRTC** 표준을 사용하여 카메라/마이크 권한 획득, 화면 캡처, 실시간 미디어 전송을 수행합니다. 따라서 기본적인 사용자 경험과 미디어 품질은 유사합니다.

### 1.2. 차이점 (Connection Topology)
*   **본 프로젝트 (P2P Mesh)**:
    *   사용자 간 **직접 연결**. (서버는 주소 교환만 돕고 빠짐)
    *   비용이 발생하지 않으며 구조가 단순함.
    *   참여자가 늘어날수록 개별 클라이언트(호스트)의 부하가 급증함.
*   **Zoom/Discord (SFU/MCU)**:
    *   모든 미디어가 **중앙 서버**를 거쳐서 재전송됨.
    *   서버 비용이 매우 높으나, 수백 명의 대규모 접속 처리가 가능함.

## 2. 파일 공유 아키텍처 (P2P Relay)
화면 공유와 마찬가지로 파일 전송 또한 참여자들의 브라우저가 직접 서버 역할을 수행하는 **P2P 방식**을 사용합니다. 중앙 서버에는 어떠한 파일도 업로드되지 않습니다.

### 2.1. 데이터 흐름 (Data Flow)
현재 구현체는 단순성을 위해 **Star Topology (Host Relay)** 방식을 채택하고 있습니다.
*   **Host가 파일을 보낼 때**: Host ➜ 모든 Viewer (직접 전송)
*   **Viewer가 파일을 보낼 때**: Viewer A ➜ Host ➜ (Relay) ➜ 다른 Viewer들

### 2.2. 특징 및 장단점
*   **보안성 (Privacy)**: 클라우드 서버 저장소(S3 등)를 거치지 않으므로 파일 유출 우려가 적습니다.
*   **속도 (Performance)**: 보내는 사람(Sender)과 중계자(Host)의 업로드 대역폭에 전적으로 의존합니다.
*   **안정성 (Reliability)**: 대용량 파일은 16KB 청크 단위로 쪼개져서 전송되며, 브라우저 메모리 내에서 재조립됩니다. (초대용량 파일에는 적합지 않음)

## 3. 로컬 교육 환경에서의 최적화 요소
이 P2P 아키텍처는 **소규모 로컬 교육 현장(강의실, 사내 연수 등)**에 최적화되어 있습니다.

1.  **경제성 (Zero Cost)**: 고비용의 미디어 중계 서버(SFU) 없이 운영 가능하므로 유지보수 비용이 사실상 '0원'입니다.
2.  **초저지연 (Low Latency)**: 같은 강의실(LAN 환경) 내에서는 데이터가 외부 인터넷을 거치지 않고 내부망을 통해 직접 전송되므로, 딜레이가 거의 없어 실시간 코딩 교육 등에 매우 유리합니다.
3.  **보안 (Privacy)**: 영상 데이터가 제3의 클라우드 서버에 저장되거나 경유하지 않고, 오직 참여자들 사이에서만 전송되므로 물리적 보안성이 높습니다.

## 4. Docker 기반 로컬 배포 가이드
외부 인터넷이 없는 폐쇄망(Intranet) 환경에서도 완벽하게 동작하기 위해서는 **웹 서버**와 **시그널링 서버** 두 가지가 필요합니다.

### 4.1. 필수 구성 요소
1.  **Web Server (Nginx/Apache)**: 학생들에게 `index.html` 등 애플리케이션 파일을 제공.
2.  **PeerJS Server (Signaling)**: 클라이언트 간의 P2P 연결을 중개(전화번호부 역할). 외부 인터넷이 차단된 경우 필수.

### 4.2. Docker Compose 배포 (실제 가이드)

프로젝트 루트에 `Dockerfile`과 `docker-compose.yml`이 이미 생성되어 있습니다. 다음 명령어로 즉시 실행 가능합니다.

1.  **컨테이너 실행 (Build & Run)**
    ```bash
    docker-compose up --build -d
    ```
2.  **로그 확인**
    ```bash
    docker-compose logs -f
    ```
3.  **컨테이너 중지**
    ```bash
    docker-compose down
    ```

**접속 주소**:
*   로컬 호스트: `https://localhost:3000`
*   네트워크(다른 PC): `https://<호스트IP>:3000` (처음 접속 시 인증서 경고 → "고급" → "계속 진행")


## 5. 확장성 및 고려사항 (Scalability)
### 5.1. 1-to-N 구조 (교육자 → 다수 학생)
*   교육자(호스트)가 1명의 학생(뷰어)에게 데이터를 보내는 부하가 `1`이라면, 5명의 학생이 접속하면 부하는 `5`가 됩니다.
*   **권장 인원**: 호스트 PC 사양과 네트워크 대역폭에 따라 다르지만, 일반적으로 **5~10명 이내**의 소규모 그룹에 적합합니다.
*   인원이 그 이상으로 늘어날 경우, 교육자 PC의 네트워크 대역폭 포화로 끊김이 발생할 수 있습니다.
